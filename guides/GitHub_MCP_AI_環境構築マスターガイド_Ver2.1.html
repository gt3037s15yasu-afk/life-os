1. 目的と完成形

VS Codeを作業場所、GitHubをライフOSの保管庫、GitHub MCP ServerをAIからGitHubへ接続する窓口として使い、 Claude CodeとChatGPTが同じリポジトリを参照・更新できる基盤を作る。

ChatGPT ──────────────── GitHub App / Connector │ │ ├─ Gmail / Calendar / Drive │ │ ▼ │ GitHub: life-os │ ▲ │ │ Claude Code ── MCP Client ── GitHub MCP Server │ ▼ VS Code / MacBook
重要：GitHub上の guides、projects、 knowledge、templates は「ブランチ」ではなく「フォルダ」。 通常運用ではブランチは当面 main のみでよい。

6. STEP3：GitHub MCP Serverを接続

GitHub公式では、VS Codeから利用する場合、GitHubがホストするRemote GitHub MCP Serverが 多くの利用者に推奨されている。通常はOAuthを第一候補とし、OAuthを使えない場合のみPATを検討する。

6.1 推奨方式：VS CodeからOAuthで接続

3-1MCP Serverを探す
  1. VS Code左側の「拡張機能」を開く。
  2. 検索欄に @mcp github と入力する。
  3. GitHub MCP Serverを選び、Installを押す。
  4. サーバーを信頼する確認が出たら、内容を確認して開始する。
3-2OAuth認証

GitHubのログインまたはアクセス許可画面が表示されたら、使用するGitHubアカウントを選択し、 許可内容を確認して認証する。

OAuthの利点：PATを手作業でコピーして設定ファイルへ書く必要がない。

3-3MCPサーバーを確認
  1. Command + Shift + P を押す。
  2. MCP: List Servers を実行する。
  3. GitHub MCP Serverが一覧にあり、開始済みまたは利用可能になっていることを確認する。

成功判定：GitHub MCP Serverが構成済みサーバーとして表示される。

6.2 代替方式：Fine-grained PAT

PATをHTML、README、チャット、スクリーンショット、GitHubリポジトリへ貼り付けない。 PATが画面に映った場合は、画像を共有する前に必ず隠す。

OAuthが使えない場合は、GitHubのSettingsからFine-grained personal access tokenを作成する。 対象リポジトリは可能な限り life-os のみに限定し、有効期限を設定する。

目的推奨する考え方
閲覧・検索のみContentsはRead-onlyを基本にする
ファイル作成・更新必要時のみContentsのRead and writeを許可する
Issue操作Issueを使う場合のみIssues権限を追加する
Pull Request操作PR運用を始めた場合のみPull requests権限を追加する

実際に必要な権限は、利用するMCPツールとGitHub側の仕様に依存する。 最初から広い権限を与えず、エラーになった操作に必要な権限だけ追加する。

Claude Code側でGitHub MCPを別途登録する必要がある構成もある。 VS CodeのMCP設定とClaude CodeのMCP設定は、必ずしも同じ設定を自動共有するとは限らない。 claude mcp のヘルプを確認し、Claude Codeで使用するMCPサーバーを管理する。

9. 秘密情報管理

対象してよいことしてはいけないこと
OAuth公式の認証画面から許可する不審な認証ページでログインしない
PAT期限・最小権限・対象リポジトリ限定HTML、README、GitHubへ直書き
環境変数ローカルの安全な設定で利用.envをGitへコミット
GitHub SecretsGitHub Actionsで使う秘密情報を登録ログへ値を表示する

推奨する運用ルール

  • PATには有効期限を設定する。
  • 不要になったPATは削除する。
  • 漏えいが疑われたら即時失効・再発行する。
  • .gitignore に .env や秘密鍵ファイルを登録する。
  • GitHubのSecret scanningとPush protectionを有効にできる場合は利用する。
